# エンティティ

エンティティとは、[シーン](scene)内（例: ノード、アセット）またはシーンをまたいで（例: プラグイン）永続するオブジェクトです。Warudoにおけるスクリプティングでは、独自のエンティティ型を定義し、Warudoランタイムとやり取りします。Warudoが提供する基底クラスを継承することで、独自のエンティティ型を定義できます。

- **ノード:** `Node`を継承して、新しいノード型を作成します。ノード型では、データ入力、データ出力、フロー入力、フロー出力、トリガーを定義できます。ノードは、ノードパレットからブループリントエディターへドラッグしてインスタンス化します。ノードのインスタンスはブループリントとともに保存されます。
- **アセット:** `Asset`を継承して、新しいアセット型を作成します。アセット型では、データ入力とトリガーを定義できます。アセットは、*アセットを追加*メニューを使用してインスタンス化します。アセットのインスタンスはシーンとともに保存されます。
- **プラグイン:** `Plugin`を継承して、新しいプラグイン型を作成します。プラグイン型では、データ入力とトリガーを定義できます。プラグインはWarudoの起動時、またはプラグインのホットリロード時に読み込まれます。プラグイン型ごとにプラグインのインスタンスは1つだけで、データ入力はシーンをまたいで保存されます。
- **構造化データ:** `StructuredData`を継承して、新しい[構造化データ](structured-data)型を作成します。構造化データは、ノード、アセット、プラグインの「埋め込み」データ入力として使用できる複雑なデータ型です。

:::info
[初めてのスクリプトを作成する](../creating-your-first-script.md)チュートリアルでは、`HelloWorldNode`というカスタムノード型と、`CookieClickerAsset`というカスタムアセット型を作成しました。
:::

:::tip
エンティティの概念はUnityのMonoBehaviourにある程度似ていますが、より構造化されたアプローチを採用しています。
:::

エンティティがインスタンス化されると、WarudoによってUUID（一意の識別子）が自動的に割り当てられます。これは`Id`プロパティからアクセスできます。このUUIDはシーン内でエンティティを識別するために使用され、シーンとともに保存されます。

エンティティ型には、通常のC#フィールドとメソッドを含めることができます。ただし、Warudoランタイムと連携するには、エンティティ内に[**ポートとトリガー**](ports-and-triggers)を作成する必要があります。すべてのエンティティには[データ入力ポート](ports-and-triggers#data-input-ports)と[トリガー](ports-and-triggers#triggers)を持たせることができ、ノードにはさらに[データ出力ポート](ports-and-triggers#data-output-ports)、[フロー入力ポート](ports-and-triggers#flow-input-ports)、[フロー出力ポート](ports-and-triggers#flow-output-ports)を持たせることができます。

## ライフサイクル {#lifecycle}

エンティティには、複数の段階で構成されるライフサイクルがあります。

- **`OnCreate()`:** エンティティの作成時に呼び出されます。インスタンスフィールドを初期化したり、イベントを購読したりする場所です。
    - **アセット:** ユーザーがシーンに新しいアセットを追加したとき、またはシーンが読み込まれたときに呼び出されます。
    - **ノード:** ユーザーがブループリントに新しいノードを追加したとき、またはシーンが読み込まれたときに呼び出されます。ノードは常にアセットの_後に_作成されます。
    - **プラグイン:** 起動時にWarudoがプラグインを読み込んだとき、またはプラグインがホットリロードされたときに呼び出されます。
    - **構造化データ:** 親エンティティが作成されたとき、またはユーザーが構造化データの配列に新しい構造化データを追加したときに呼び出されます。
- **`OnDestroy()`:** エンティティの破棄時に呼び出されます。リソースを解放する場所です。
    - **アセット:** ユーザーがシーンからアセットを削除したとき、またはシーンがアンロードされたときに呼び出されます。
    - **ノード:** ユーザーがブループリントからノードを削除したとき、またはシーンがアンロードされたときに呼び出されます。ノードは常にアセットの_後に_破棄されます。
- **`Deserialize(TSerialized data)`:** 保存された状態からエンティティがデシリアライズされるときに呼び出されます。たとえば、シーンを開いて読み込んだ直後、アセットでこのメソッドが呼び出されます。_通常、このメソッドをオーバーライドする必要はありません。_
- **`Serialize()`:** エンティティを保存された状態にシリアライズする必要があるときに呼び出されます。たとえば、シーンを保存しようとするとき、またはエディターに送信する必要があるときに、アセットでこのメソッドが呼び出されます。_通常、このメソッドをオーバーライドする必要はありません。_

アセット、ノード、プラグインには、追加のライフサイクル段階があります。

- **`OnUpdate()`:** エンティティが破棄されていない間、毎フレーム呼び出されます。Unityの`Update()`メソッドに似ています。
  - `OnPreUpdate()`と`OnPostUpdate()`も提供されています。これらはそれぞれ、`OnUpdate()`の前後に呼び出されます。
- **`OnLateUpdate()`:** `OnUpdate()`の後、毎フレーム呼び出されます。Unityの`LateUpdate()`メソッドに似ています。
- **`OnFixedUpdate()`:** 固定フレームごとに呼び出されます。Unityの`FixedUpdate()`メソッドに似ています。
- **`OnEndOfFrame()`:** フレームの終わりに呼び出されます。Unityの[`WaitForEndOfFrame`コルーチン](https://docs.unity3d.com/ScriptReference/WaitForEndOfFrame.html)の使用に似ています。
- **`OnDrawGizmos()`:** エンティティがギズモを描画する必要があるときに呼び出されます。Unityの`OnDrawGizmos()`メソッドに似ています。

:::info
更新順序は次のとおりです: プラグイン → アセット → ノード。
:::

これらのライフサイクルメソッドをオーバーライドして、エンティティのカスタム動作を実装できます。たとえば、毎フレーム何かを実行したい場合は、`OnUpdate()`メソッドをオーバーライドします。
